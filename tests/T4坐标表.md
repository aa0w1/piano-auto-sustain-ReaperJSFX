逐行复算方法：先算「设计坐标公式」列（纯设计单位，全部来自集中常量），再按布局引擎换算两档。

## 布局引擎（ui_frame_begin）

```
ui_sc = min(gfx_w / 380, gfx_h / 460)；ui_sc < 0.75 时钳为 0.75
ui_ox = (gfx_w − 380×ui_sc) / 2        （内容框水平居中）
ui_oy = (gfx_h − 460×ui_sc) / 2        （内容框垂直居中）
屏幕坐标 = ui_ox + 设计x×ui_sc；屏幕 y 同理；宽高 = 设计值×ui_sc
```

- **@380×460**：ui_sc = min(1, 1) = 1，ui_ox = ui_oy = 0 → 数值 = 设计值。
- **@760×920**：ui_sc = min(2, 2) = 2，ui_ox = ui_oy = 0 → 数值 = 设计值 × 2。
- 非 380:460 比例的窗口：等比取 min 后居中，多余边留白（设计取舍，见文末偏离记录 6）。

## U1 渐变实现方式与每帧开销（自检6）

**选择：直接每帧调原生 `gfx_gradrect`（经 ui_grad_v / ui_grad_h 帮助函数），未用离屏缓冲。**
理由：gfx_gradrect 是 REAPER 原生 C++ 渐变填充（单次调用、非 EEL2 逐像素循环），两大底每帧重绘开销
可忽略（3 次 gradrect + 3 条 rect 完成全窗背景），离屏缓冲（gfx_setimg/gfx_blit）在本布局下只增加
「尺寸变化时重建」的复杂度而无收益。全部线性渐变走帮助函数：乌木两段（三停 0/100/172）、象牙一段、
立柱两段（三停 45%）、嵌线两段（三停 50%）。**唯一例外：踏板面**——「圆角 12/9 + 垂直三停渐变」
单次 gfx_gradrect 无法同表（无圆角裁剪），采用逐行 1px 矩形（每行一 gfx_rect，行色三停插值+圆形角
内缩；sc=1 时 26 行 / sc=2 时 52 行），阴影椭圆同理逐行（7/14 行）——合计每帧 ≈90 个小矩形，60Hz 下
开销可忽略。步进 = (终−起)/(跨−1)，跨 ≤1 退化为纯色矩形。签名（B1 修复，官方文档核实）：
`gfx_gradrect(x,y,w,h, r,g,b,a[, drdx,dgdx,dbdx,dadx, drdy,dgdy,dbdy,dady])`——alpha 为第 8 参
（传当前 gfx_a 保持透明度语义）；垂直= y 向三增量走 drdy/dgdy/dbdy、x 向全 0；水平反之。
